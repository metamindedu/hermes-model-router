# 모델 선택 UI

설정 화면의 모델 선택은 호스트 공개 SDK의 `ModelCatalogMenu`(입력창 모델 선택과 같은 메뉴)를 그대로 쓴다. 자체 목록을 만들거나 메뉴를 복제하지 않는다. 메뉴는 namespace import로 조회하며, 없는 호스트에서는 공급자·모델 ID 입력을 그대로 보여 준다. 이 때문에 `requires_hermes` 하한은 올리지 않는다.

## 선택의 의미

메뉴는 기존 필드 updater로 **초안만** 고친다. 저장 경로·payload·적용 대상 규칙은 그대로다.

- 모델을 고르면 공급자·모델만 바뀐다. 역할에 저장된 추론 강도는 유지한다. 메뉴가 넘겨 주는 모델별 기억값·기본 강도는 강도가 **비어 있을 때만** 받는다.
- 행의 강도 메뉴에서 명시적으로 고른 경우에만 강도가 바뀐다. 각 행은 그 역할의 현재 강도를 미리 보여 준다.
- 예비 모델 항목은 강도를 저장하지 않으므로 강도 편집을 무시하고, 화면에 그 사실을 적는다. 메뉴에서 강도 항목만 숨기는 공개 옵션은 없다.
- 강도 Select는 백엔드 `EFFORTS`와 같아야 한다(테스트가 `service.py`와 대조). 목록에 없는 저장값은 지우지 않고 그대로 표시한다.

## 목록 읽기

`model.options`는 연결의 프로필과 `profile` 인자가 다르면 `profile_mismatch`로 거절한다. 활성 프로필은 연결된 소켓으로, 다른 불러온 프로필은 새로 조회한 정확한 local route descriptor로만 읽는다. alias·중복·원격·누락 경로는 읽지 않고 ID 직접 입력을 안내한다. 메뉴를 열 때만 읽고, `explicit_only`로 고정하며 refresh나 다른 메서드는 통과시키지 않는다. 목록은 **불러온 프로필** 기준이며 저장 대상 프로필을 따라가지 않는다.

## 함정

- 목록 행의 React key에 편집 중인 값(공급자·모델)을 넣으면 입력할 때마다 행이 다시 마운트되어 포커스와 펼침 상태가 사라진다. 위치 기반 key를 쓴다.
- 위치 기반 훅을 쓰는 테스트 하니스에서, 조건에 따라 나타나는 훅 컴포넌트는 페이지와 훅 목록을 공유하면 상태가 섞인다. 별도 scope로 렌더한다.
- 렌더러 fixture(`scripts/render_model_picker_fixture.mjs`)는 실제 native 컨트롤·메뉴와 가짜 host·목록의 조합이다. 설치된 앱에서의 실제 목록 읽기와 테마는 별도로 확인한다.
