# Small changes stay with Main

Ordinary implementation delegation is a cost decision, not a default ritual. Keep bounded fixes and their checks with Main unless a child has a net benefit after startup, context transfer and coordination: a different-model route the task needs, context weight, long runtime, or at least two substantive independent workstreams (see below). Do not count an edit's tests/build/optional review as another implementation workstream or artificially split it. Apply the same threshold before routing-tool discovery and to native delegation.

Since v0.12.0 the criteria also weigh the model. When a slot runs on Main's own model, a child adds only a fresh context, so delegate only for context weight (large tool output, many screenshots), long runtime (Main stays responsive while it runs in the background) or at least two substantive independent workstreams. Design and planning stay with Main in that case. Short screen actions stay in Main and long screen sessions go to a `computer-use` child. A different model counts only when the task needs that slot's role; an available Light route alone does not. Independent and final reviews are still fresh children whatever the model, and a required Heavy review is never folded into Main by these criteria.

A required Heavy/independent review may be a single child; preserve high-risk judgment, project gates and production approval without manufacturing extra implementation jobs. Explicit user delegation is a separate exception. Main retains visual/motion design and small review corrections.

Since v0.16.0 Main can also consult the advisor (`ask_advisor`, the Heavy `advise` slot) at a decision point without handing the work off: one question, a read-only child, and the answer in the same tool call. It is skipped when the slot runs on Main's own model, and it never replaces a required Heavy or independent review. See [[task-slots]].

The rule is agent guidance, not an API two-job minimum or a new router denial. Distribute the reviewed common delta while preserving profile-local handoff additions and manifest differences. Read back installed bytes and unchanged user-state hashes; new Python descriptions may need a new session. Public release, catalog PR/CI, maintainer merge and docs search visibility are distinct states. See [[index]].
