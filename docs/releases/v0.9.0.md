# v0.9.0 — Execution visibility and opt-in profile jobs

Requires Hermes **>=0.23.1**. This independent community plugin does not modify Hermes core.

## Added

- A focused-conversation execution roster distinguishing native Heavy/Light, native profile delegation and separately Gateway-owned full-profile jobs. Unknown identity correlation remains unknown.
- Explicitly opt-in `profile_task` start/status/stop/steer and visible-result collection, using the target profile's normal `tool`-surface policy and an existing compatible Gateway. No private agent executor, owner start/recovery, model/tool override or silent native-delegation replacement.
- Original host-operator CLI grant review/configuration with stable revision checks and exact native setter readback. Sensitive approval/clarification decisions stay in the exact native target conversation; plugin RPC cannot grant itself access or relay a decision.
- Current raw/effective permission agreement, preventing stale last-known-good grants from reviving a revoked or removed policy. Long/incomplete pending command text remains read-only.
- Durable bounded identities and workspace claims, no automatic replay after uncertain writes, and explicit recovery/result-delivery limitations.

## Defaults, account use and verification

Installation/activation does not change models, execution-backend choices, budgets, existing fallback consent or profile access grants. Full-profile jobs default OFF with an empty allowlist. Enabling the package is not permission to use another profile's account/tools/memory, nor does it rebuild an existing conversation's pinned tools. Completion requires explicit result collection; it does not automatically wake the parent.

The existing PyYAML dependency remains bounded at `>=6,<7`; the canonical WebSocket client adds `websockets>=15,<17`, resolved through Hermes's normal dependency manager under its core constraints. No plugin-specific telemetry, self-updater or credential store is added. Pending/result prose and job journals remain private material.

Isolated source acceptance covered real native getter/setter/CLI/authorization boundaries, synthetic target transport and responsive native-component fixtures. Those tests do not certify live target/provider/MCP/memory behavior or billing. Installation, loaded registration, current-session tools and real provider execution are separate evidence levels.

## Upgrade and rollback

Use normal Hermes exact-SHA installation and review native scan/dependency prompts. Do not force a shared restart or reset ongoing conversations just to refresh tools. Preserve local guidance edits and user data. The prior public v0.8.0 release is the code recovery point; a downgrade requires separately reviewing any newer saved backend/policy selection rather than silently rewriting configuration or assuming old code understands it.
