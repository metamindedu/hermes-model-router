# v0.18.1: Custom slot limits follow their definition

## Fixed

- Removing a custom slot now also removes its runtime limit from every profile's `timeouts.json`, in the same save as its model declarations. Before, the limit stayed in the file, and defining a slot again under the same ID brought the old limit back instead of the two-hour default.
- Any custom slot save first drops limits left over for IDs that are not currently defined, so an ID it defines always starts on the default. Those limits had no effect, because the slot did not exist.
- The save preview lists each profile whose limits are removed. If removing a limit fails after the definitions were saved (for example, the file changed since the preview), the save reports `partial`, the page names those profiles, and the next custom slot save removes the leftover. A profile whose timeouts file cannot be read is left untouched.

## Unchanged

No storage format changes; no migration. Built-in slot limits, the ordinary delegation limit and every other profile setting are not touched by a custom slot save.

## Upgrade

Install v0.18.1 in every profile and restart Desktop and the gateway. No conversion is needed from v0.18.0.
