# v0.15.0: Section saves send only changed values

- Behavior change (owner decision): picking save targets by hand no longer copies the loaded profile's whole settings. A save sends the values you changed, and each selected profile keeps every value you did not change. To copy the loaded profile's current settings to the selected profiles as before, tick the new "현재 설정 전체 복사" checkbox in that section's target list. The checkbox starts unticked and resets after a successful save, a reload, a profile switch, or any change to that section's target list.
- This applies to the model section (role models, task-slot models, the delegation method, per-slot spare models, conversation and compression/title spare models), the time-limit section, the profile-delegation section and the whole-page save. Role models and spare-model chains were already sent per changed role or chain (v0.14.0); only their copy intent moved to the checkbox. A changed spare-model chain is still sent as a whole chain.
- With a service that reports `partial_save_schema: 1`, the page sends partial request forms, each marked with a literal `partial_save_schema: 1`: only the edited task slots (merged over each target's stored slots; Heavy/Light are left out), only the changed time-limit fields (merged with each target's own values), the method only when edited plus a per-slot spare-model patch, and an allow-list patch (added, removed and re-described profiles, the default only when edited). Unsent values, absent keys and existing cost consent stay exactly as stored. For slot models the compare-and-set now covers only the slots written, so a sibling slot changed elsewhere no longer blocks the save; a written slot changed elsewhere still refuses the whole save before anything is written. A partial save that also sends Heavy/Light must freeze them in full. The delegation-method, spare-model and allow-list saves still compare each target's whole delegation settings (its digest), and time-limit saves each target's whole time-limit revision, so any change there made elsewhere refuses the save (stricter than per value).
- Kept protections: another profile's slot that still follows the delegation model is not overwritten (the page names it), another profile storing two-role spare models is not patched per slot (named, with the way out: load and save that profile, or use copy-all); the loaded profile's own two-role block is replaced as a whole by its per-slot view when its spare models are saved, as before; a new allow-list grant still needs the explicit access confirmation, and every write is compare-and-set per target.
- A partial save never sends a default specialist profile to a target whose list does not hold it, or to a target on automatic model / profile selection (which does not use a default): that target keeps its own default and is named. Each target's summary line lists only what actually changes there.
- The whole-page save is disabled, and sends nothing, while nothing would be written.
- Request bodies without the marker keep their earlier meaning exactly, and the page keeps sending them to a service without the capability. Install the same version on every profile.
