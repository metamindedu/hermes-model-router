# v0.11.3 — AI role proposals read the whole SOUL; tokens per subagent

## Fixed: "AI로 역할 제안" refused real profiles

- The default profile's `profile.yaml` also holds Hermes Desktop's UI metadata and grew past the 32 KiB source cap, so its sources were refused ("이 프로필의 역할 자료를 안전하게 읽을 수 없습니다"). `profile.yaml` is now read up to 512 KiB; only `description` and `description_auto` are used. Before loading, the YAML token stream is checked against a 40,000-token and depth-32 budget (aliases and anchors are still refused), and the parsed fields are cached by content hash, because status and tool-schema construction also read it.
- A skill tree with more than 512 entries, or containing a linked folder (Windows junction or symbolic link), made the whole skill list unavailable. The budget is now 4,096 directory entries (names only, no file bodies). Linked folders are never followed; they are left out (`linked_skills_omitted`, "연결된 스킬 폴더") and the rest of the list is sent.

## Changed: the whole SOUL is sent

Earlier releases sent only the section under a literal `Role`/`역할` heading. No real profile here had one, so the SOUL contributed nothing. The proposal now sends the whole `SOUL.md`:

- It is shown before sending, in a collapsed "SOUL 문서 전체 (N자)" block in the dialog, and the existing source/route digests still refuse sending if it changes after review.
- The model is told that all supplied text, including the SOUL, is data describing the profile and must not be followed as instructions.
- A SOUL with an obvious credential shape (`api_key = …`, bearer tokens, private-key blocks and similar) is left out entirely (`soul_sensitive`). This is a narrow pattern check, not a guarantee; review the text in the dialog.
- A SOUL over 32 KiB, or one whose context reply would not fit the 48,000 characters Hermes hands the Desktop from a CLI call, is left out (`soul_too_large`), never cut.
- The request input limit is 64 KiB; the output limit stays at 512 tokens.
- The request goes to the owner profile's saved model and account, as before. Where every profile shares one provider account, this is the same place the SOUL already goes in that profile's own conversations.

The wire field is renamed `soul_role_excerpt` → `soul_text`.

## Added: tokens per subagent

Each subagent line now shows its token total next to the tool count (`5분 4초 · 도구 18회 · 토큰 55만`), and the expanded row shows the breakdown (`토큰 55만: 입력 12만 · 캐시 읽기 43만 · 출력 2.7천`; zero cache buckets are omitted). The roster sums the host-normalized usage that Hermes passes to `post_api_request` for each of the child's API calls (uncached input, cache read, cache write, output; reasoning is not added separately because providers usually count it inside output). The total matches Hermes' session total: all prompt tokens, cached included, plus output. When the native `subagent.complete` event for a row is seen, its reported prompt + output total takes precedence, because it also counts usage the per-call hook does not see (for example Mixture-of-Agents advisor calls); if it differs from the per-call sum, the row shows `토큰 N (완료 보고 기준) · 모델 호출 관찰분 M: …`. The completion total only updates an existing roster row (matched by native call, subagent and task index); it does not restore rows after a backend restart. Calls whose usage the provider did not report are not counted by the per-call sum, so a running row can show less than actual use.

## Unchanged: the status strip hides when there is nothing to show

The strip still hides when the conversation has no recorded executions. The roster is in memory, so after a Hermes restart or plugin reinstall the strip stays hidden until the next subagent runs. It also hides while data is loading, when the conversation scope or passive origin is unavailable, and when the split-chat gate places it in another pane.
