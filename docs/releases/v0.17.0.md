# v0.17.0: Custom task slots

## Added: up to four operator-defined task slots

The settings page has a new **사용자지정 슬롯** section. An operator defines up to four extra slots, shared by every profile, each with:

- an id `custom:<name>` (`<name>`: 2-32 lowercase letters, digits or hyphens, starting with a letter or digit). The id is also the `purpose` the agent sends and cannot be changed after saving;
- a label (1-24 characters) and a one-line scope description (1-120 characters). Leading/trailing spaces and Unicode categories Cc, Cf, Cs, Zl and Zp are refused (controls, bidirectional and zero-width format characters, emoji joiners (ZWJ), soft hyphens, tag characters, lone surrogates, line/paragraph separators), so a ZWJ emoji such as `👩‍💻` cannot be used;
- a tier, `heavy` or `light`, which sets the runtime limit, watchdog role, runtime label and the default model of a profile that never set the slot.

Each profile then picks the slot's model on its slot card, exactly like a built-in slot. Built-in slots cannot be removed; custom slots can.

The purpose enum of `delegate_task` (`model-router` and `model-router-auto`) gains the defined ids after the built-ins. The purpose field description lists each custom slot's id, label and scope as JSON marked as untrusted descriptive data, not instructions.

Custom slots choose the **agent LLM** for a kind of work. Image and video generation models stay in the `image_generate` / `video_generate` settings.

## Behaviour

- Definitions live in `settings.json` as a top-level `custom_slots` list and are saved through their own `custom-slots-preview` → `apply` plan, separate from profile settings. A stale revision is refused.
- Removing a definition removes that slot's model declaration from every profile in the same write; the preview lists the profiles affected.
- A `custom:` purpose that is not currently defined is refused at execution time. Sessions opened before a definition changed keep their old enum until a new session starts.
- Custom slots have no spare models: per-slot spare-model blocks name only built-in slots, and custom slot tasks run with `fallback_providers: []`. A profile still on a two-role (schema 1) spare-model block applies that tier's chain, as for built-in slots.
- The status line shows a custom slot child as `모델 · <label>`.
- A custom heavy slot is not a review purpose. Required Heavy and independent reviews still use `semantic-final` / `independent-review`.

## Upgrade order

The settings file is schema 4 only while `custom_slots` exists; removing every definition returns it to schema 3 or 2. Packages before 0.17.0 refuse a schema 4 file (fail-closed). Saving a definition is blocked until every installed profile's `slots.py` matches this release, checked at preview and again at apply; removing every definition stays possible.

1. Update every profile to 0.17.0.
2. Restart every Hermes process (Desktop windows, gateway).
3. Then save the first custom slot.
