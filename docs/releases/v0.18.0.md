# v0.18.0: Per-slot runtime limits

## Changed: slot models and time limits

v0.18 removes the Heavy/Light classes. Every slot follows the profile's Main model or uses its own model. A slot that has never been configured runs on Main.

Each slot row on the settings page has a model and a total runtime limit in minutes. Leave the time empty for **2 hours (7200 seconds)**. Enter `0` for no plugin total limit on that slot. Ordinary and profile-routed delegation have a separate limit, off by default. `coding_route(action="config")` reports `slot_timeout_seconds` and `delegate_timeout_seconds`. The native per-task `total_timeout_seconds` override uses seconds and should normally be omitted.

## Behaviour

- Built-in slots are `design`, `code-complex`, `code-simple`, `verify-simple`, `verify-complex`, `computer-use` and `advise`. Operators can still add up to four shared custom slots. A definition contains only an ID, label and one-line description; its ID doubles as its purpose.
- The bundled orchestration policy is version 2.0.0. Required planning and reviews use the named purposes `plan`, `semantic-final` and `independent-review`. `preliminary-review` cannot satisfy them. The `advise` purpose runs only through the read-only `ask_advisor` tool.
- `model-router` reports the slot ID; `model-router-auto` reports `model:<slot>` or `profile:<name>`. Rows in `execution-roster/2` carry the slot for model-routed work.
- Native spare models continue the same child. Each built-in slot needs its own exact-chain cost consent for the profile and backend. The plugin no longer reruns tasks on a spare model after subscription exhaustion. Hermes conversation fallback and ordinary delegation fallback remain separate.
- `coding_route` has only the `config` action. The process launcher, worker and status/join paths were removed. The plugin cannot inspect or join historical process jobs. Native `delegate_task` and separately authorized Gateway-owned `profile_task` jobs are unaffected by that removal.

## Upgrade order

v0.18 reads only settings schema 5, timeout schema 3 and slot-only native continuation blocks (schema 2). The settings page reports incompatible settings, routing fails closed, and invalid timeout files are read-only. A profile cannot save timeouts without the literal `SLOT_TIMEOUTS_SUPPORTED = True` in its installed `model_router/timeouts.py`.

1. Install the v0.18 files in every profile.
2. From the package directory, run `python scripts/migrate_to_v018.py` with the Python environment that runs Hermes. This is a dry run. Review the report, then run `python scripts/migrate_to_v018.py --apply`.
3. The operator restarts Desktop and the gateway. If they were restarted before the migration, migrate immediately and restart them once more so the routing policy is registered. The agent does not restart either process.

The one-time script preserves each slot's effective v0.17 model. Runtime limits restart from the default: every slot runs on the 2-hour default until a limit is entered, and the ordinary delegation limit is kept. A slot that used the delegation model is pinned to that model, not linked to future delegation-model changes. Timeout files in schema 1 or 2 become schema 3 with no per-slot limits; all-off two-role native blocks become all-off per-slot blocks. The script refuses enabled routing spares, stored routing consent, enabled spares in a two-role block or unknown shapes without writing a conversion. Before replacing a file it keeps the original once as `<file>.pre-v018`. Output contains no model names, routes or secrets.
