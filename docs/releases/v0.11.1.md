# v0.11.1 — No layout pane; execution rows show the model that ran

## Removed: the "실행 현황" bottom pane

Hermes Desktop disables a plugin as a whole when the user closes the only layout pane that plugin contributes. The execution pane was Model Router's only pane, so closing it switched off the plugin, its settings page and the composer status line together, and the plugin showed as Off in the plugin list.

The pane is gone. The same rows remain in the composer status line above the input (expand it for the full list), and Hermes' own subagent cards still carry progress and stop/steer controls.

## Fixed: "실행: 미확인" on every row

The "실행" line only used a route report from the synchronous delegate result. Background delegations never return that report, so every background row said 미확인 even when the child's own API calls had already reported its model.

- The "실행" line now shows one model/provider pair from one source, labelled with that source: the child's own API calls ("API 호출 기준"), else a route report ("런타임 보고"), else the native roster's start-time assignment ("시작 시 배정 · 예비 모델 전환 미반영"). It says "아직 API 호출 보고 없음" when none is known.
- The requested identity names the slot ("모델 · 코드 · 간단") instead of only the Heavy/Light tier.

## Redesigned: the composer status line

- Running subagents first (newest first), then finished ones by most recent change.
- Collapsed: `서브에이전트 · 실행 중 N · 완료 N · 오류 N · 중단 N · 미확인 N` (only confirmed completion counts as 완료) and up to two chips `slot · model · elapsed`, or the latest finished one. Hidden when the conversation has no executions.
- Expanded: one line per execution (status, slot, model, time, tool count); click a line for model source, activity and IDs.
- Full-profile job controls (stop, steer, result, open target) open from the job's own line; the allowed-targets and operator guide is at the end of the list and loads only when opened. With no executions in the conversation the guide is not shown.

No settings or stored-format changes.
