# v0.11.4 — Saving many profiles at once; faster settings

## Fixed: saving for many profiles was refused as too long

The page reaches the plugin through Hermes' `cli.exec`, which passes the request body as one command-line argument; on Windows a command line holds at most 32,767 characters, so the page refused bodies over 16,384 characters ("한 번에 저장하기에는 내용이 너무 큽니다"). A delegation save for all 11 profiles copies each target's routes and descriptions and exceeded that.

Bodies over 12,000 characters are now staged: the page sends the JSON text in numbered pieces through a new `stage` operation (each piece under one command line, never splitting a surrogate pair), then sends `{"staged": {"id", "total", "length"}}` as the real request (`length` in UTF-16 code units, as JavaScript counts). Every piece and the final request go to the one gateway that was live when the transfer started; if the gateway, connection or active profile changes, the transfer stops before the next call. The plugin assembles exactly that text, checks every piece and the total length, deletes the pieces, and runs the request unchanged. Only `preview`, `fallback-preview`, `delegation-preview` and `initial-setup-preview` accept a staged body; `apply` and role proposals do not. Pieces live under the profile's `plugin-data/model-router/staged`; every component of that path is checked for links and junctions before anything is written, read or removed there, and pieces are read through a handle checked against the inspected file. Abandoned pieces and temporary files expire after 10 minutes. The page caps a body at 400,000 characters and 128 pieces (an escape-heavy body can reach the piece cap first).

## Fixed: editing stayed locked after a save until a manual refresh

After a confirmed save (`applied` or `no_change`, not partial) the page now reloads the saved state by itself and editing continues; the success note stays. A reload replaces every draft on the page, so it runs by itself only when the save covered every unsaved edit; when other parts of the page still hold unsaved edits, the page says so and keeps them until you reload explicitly. Partial or unknown results still wait for "실제 상태 확인 후 편집 재개", as before.

## Faster: settings status and saves

A status read parsed each profile's `config.yaml` about fifty times. Parsing is now memoized by exact content (SHA-256 of the text; callers get deep copies, errors are not cached), Hermes' raw config read is memoized while the file config backend is selected (the memo parses exactly the bytes it is keyed by, with the host's own loader), and within one status or delegation-preview call the profile list and the source package identity are computed once. One status page went from about 16 to about 5 seconds here; the whole 11-profile status from about 30 to about 14 seconds in one process.
