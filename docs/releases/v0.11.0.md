# v0.11.0 — Task slots and one model section

## Changes

- A delegated task's model is chosen per task slot, set directly on each slot: `design`, `code-complex`, `code-simple`, `verify-simple`, `verify-complex`, `computer-use`. There is no simple-design slot; small design stays with the main model.
- Purposes keep their names and map to slots: `plan` → design, `implementation` → complex code, `mechanical` → simple code, `preliminary-review` → simple verification, `semantic-final` and `independent-review` → complex verification, and the new `computer-use` → computer use. Tier (heavy/light) remains for the two routed runtime limits, the watchdog role, the runtime label and the meaning of a slot that was never set.
- Spare (continuation) models are per slot. A per-slot save writes block schema 2 with new exact-chain cost consent bound to slot, backend, profile and chain. A stored two-role block stays valid, is applied by tier, and is never rewritten on read or reused as slot consent.
- The settings page has one `모델` section with one target list, defaulting to the loaded profile only, and one save button running the two existing transactions in a fixed order. The routing on/off control and the Heavy/Light editors are removed from the page; profiles saved with routing off get a separate re-enable save.
- The model picker introduced for the conversation roles is used for slot models and spare models.
- The page reads settings status in size-bounded pages. Hermes returns at most 48,000 characters of one CLI call's output, and the status of many profiles is larger than that. `status` without a body still returns everything in one reply.

## Compatibility

- An install that never saves a slot resolves every existing purpose as before; nothing is migrated on read. `settings.json` becomes schema 3 only while some profile stores `routing.slots`, and returns to schema 2 when all are cleared.
- Slot saves in the shared settings file are accepted only when every installed profile's package can read them, checked at preview and again at apply for a plan that adds or changes slots. A save that only removes slots is never blocked at apply. A per-slot spare save needs only the target profile's own package.
- `coding_route(action="config")` adds `slots`, `slot_tiers` and `purpose_slots`. `heavy` / `light` stay for historical readers and describe never-set slots only.

## Upgrade order (required)

1. Update the plugin in every profile that has it installed.
2. Restart every Hermes process: Desktop, gateways and open sessions.
3. Only then save a slot model or a per-slot spare model for the first time.

The capability check reads packages on disk and cannot see a process that is still running the previous code. After the first slot save such a process refuses settings reads and purpose routing for every profile sharing the store, and after a per-slot spare save for that profile, until it is restarted. It fails closed and writes nothing. The page shows this reminder while no slot setting has ever been saved.

## Not included

Operator-added slots, per-slot runtime limits, removal of the legacy fallback section, and any change to Hermes core. `computer-use` children driving a real browser or desktop were not exercised. The body limit of one settings request is unchanged (16,384 characters); the page refuses a larger request before sending and asks for the targets to be split.

## Verification of this source

Node suites and the full Python suite were run on the committed tree; the Python failures are the same real-Hermes-core integration tests that fail on the previous release in the development environment. The page was exercised in an isolated renderer with real native controls and invented profiles at desktop, tablet and mobile widths. Two independent read-only reviews preceded the corrections recorded in `docs/handoff/2026-11-17-slot-settings-page.md`.

This file describes the source at this version. A Git tag, GitHub release and official-catalog pin are separate steps and are not implied by it. Automatic preparation of a newly created profile is unavailable in this version, as in v0.10.0 (the release identity check does not accept the two declared tools), so such a profile is prepared manually.
