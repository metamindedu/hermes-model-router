# v0.13.1: Running subagents survive a plugin reload, recommended presets removed, auxiliary CAS hardening

This is a patch release. It changes no Hermes core code, adds no write path and does not migrate or rewrite stored values.

## Fixed: a running subagent lost its execution kind and model tracking after a plugin reload

**Symptom.** A native subagent started with `execution: model` (for example `purpose: independent-review`). While it ran, the plugin was reinstalled (`hermes plugins install … --force --enable`). The CLI then asked the running gateway to reload plugins. After that, the page showed the child as **요청: 실행 종류 미확인**. Its model was shown as the start-time assignment (`시작 시 배정 · 예비 모델 전환 미반영`), although the child had switched to a spare model.

**Cause.** A forced plugin reload (`reload-plugins` → `discover_plugins(force=True)`) runs inside the same gateway process. It unloads every hook and RPC of the plugin, evicts the `hermes_plugins.<slug>.*` modules and calls `register()` again. `register()` built a new execution roster with empty in-memory state. The running child's row, its correlation and its counters were lost. Later hooks of that child (`pre_api_request`, `post_api_request`, `subagent_stop`, …) found no row to update. The page then had only the uncorrelated native live row to show.

**Fix.** The roster state now lives in one process-global holder: a plugin-owned module `hermes_model_router_runtime_state` in `sys.modules`, which the plugin loader never evicts. The state is keyed by the resolved profile home and tagged with a schema (`execution-roster/1`). The shared state covers rows, children, session aliases and pending continuations, and its lock is shared too.

- **One live instance.** The newest registration owns the state. An earlier instance becomes inert: its hooks and its `execution.list` do nothing. A stale hook that still fires therefore never counts tool calls, API calls or tokens twice. Core already removes the old hooks on reload; this is defence in depth.
- **Every path continues.** The pre/post tool hooks, `subagent_start`/`subagent_stop`, `post_compaction`, `pre_api_request`/`post_api_request` and `action: continue` all work across a reload. This includes a reload between a continue call and the start of the continued run.
- **Incompatible state is discarded.** A state of another schema, or one that fails validation (row/child shape, status values, token buckets, bounds), is dropped as a whole. Rows then read as unknown and are never attributed to the wrong run. The previous instance is retired before its state is dropped.
- **Nothing on disk.** The holder keeps the same bounded, in-memory metadata as before: ids, counters, statuses and model/provider ids. It never holds task, prompt or result text, or secrets. It is lost on a process restart, as before.
- Another profile's registration never retires this profile's roster.

An upgrade from v0.13.0 still starts with an empty roster once, because v0.13.0 kept no shared state.

## Removed: the recommended model presets (추천 구성)

The **모델** section no longer shows the **추천 구성** block. Removed: the OpenAI and Non-OpenAI cards with **초안에 채우기**, the hint, and the line **현재 모델은 사용자 지정 조합입니다.** Edit each model in its card. Everything else in the section is unchanged.

The now-dead page code is gone: `MODEL_PRESETS`, `selectedModelPreset`, `applyModelPresetDraft` and the preset styles. No service or status field existed only for the presets, so no service contract changed. The routing-fallback presets (`ROUTING_FALLBACK_PRESETS`) are separate and unchanged.

## Hardening (from the v0.13.0 review)

- **Fail-closed auxiliary compare-and-set.** A plan's per-key digest map no longer passes vacuously:
  - A written `auxiliary.<task>.fallback_chain` key without its own recorded CAS digest refuses the plan at preview end and at apply start.
  - A written key without its own provenance digest refuses that write.
  - A written profile missing from either map, an empty map or a non-string digest also refuses. Nothing is written in any of these cases.
- **Old plans.**
  - A one-string plan from before the per-key digests is still checked over both keys, as before.
  - A v0.13.0 plan that carries the unused `auxiliary_snapshot_keys` field still applies.
  - New plans no longer write that field. The `auxiliary_snapshots`/`auxiliary_provenance` annotations now state the per-key map shape.
- **Uniform status row.** An auxiliary task whose snapshot cannot be read now reports the same fields as a readable task. Its `env_masked` is `false`, and `primary` is the task's own model, or `null` when not known. The row stays read-only with `warnings: ["auxiliary_fallback_unavailable"]`.

## Safety (unchanged)

All v0.12.x and v0.13.0 guarantees still hold:

- per-profile `expected` compare-and-set
- the store digest check at apply start and immediately before `os.replace`
- preservation of untargeted entries
- absent keys staying absent
- per-key auxiliary snapshots, provenance and readback
- cost confirmation for every write that sets spare models
- dirty tracking, staged transfer, save fences and generation tokens
- structured `ExternalChange` errors
- no automatic retry of a partial or unknown outcome
