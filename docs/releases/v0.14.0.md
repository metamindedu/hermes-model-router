# v0.14.0: Follow Hermes model settings without re-saving

- Model Router reads the profile's current Hermes settings for conversation, ordinary delegation, compression and title generation. Normal edits made in Hermes settings or by CLI are not a route-wide configuration conflict. This is a read-time projection, not a background sync or a write to every profile.
- A slot configured to follow a native model uses that profile's verified current route on its next dispatch. Explicit slot models, spare-model policies, grants and cost approval are not changed. Ambiguous or unmanaged-by-the-router destinations are not guessed; only dependent slots refuse them.
- Desktop model saves write the edited roles, or roles explicitly selected for copy. Concurrent changes to the same role block stale saves. Unrelated roles are not overwritten or pinned, including compression/title settings inherited from the primary model.
- The conversation spare-model display reflects the effective Hermes chain. Reading an external change never grants plugin cost consent. Existing profile configuration and plugin store formats are retained; rollout the same version to all installed profiles.
