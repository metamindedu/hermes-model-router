사용자가 전체 프로필 선택 후 저장해도 불러온 프로필만 바뀌는 문제를 보고했다. 활성 목록과 경로 복사 범위를 분리한다. 선택적 `routing_targets`가 없으면 기존 `[profile]`, 명시적 빈 배열이면 경로 미변경, 지정한 목록에는 Heavy/Light 선언만 복사한다. enabled는 `routing_profiles`, 모델은 `model_targets`, 폴백·비용 허용은 기존 별도 경로를 유지한다. 각 대상의 따라가기는 그 대상의 최종 모델로 해석하고 최종 충돌 검사를 유지한다.

UI에는 Heavy/Light 설정 적용 대상 목록과 전체 선택·불러온 프로필만·모두 해제를 제공한다. 초기 전체 선택 자체는 복사 의도가 아니다. Heavy/Light 기준값과 실제 변경 차이 또는 직접 대상 선택이 있는 저장에서만 복사한다. 기준 프로필 변경·실제 상태 새로고침에서 일회 복사 의도를 지우고 수동 대상 선택은 유지한다. 수정한 경로의 대상이 없으면 저장을 차단한다. 모델-only·활성화-only 저장은 다른 프로필의 경로를 보존한다. 기존 저장 잠금·revision/CAS·부분 실패·단일 적용 계약과 폴백 최종 검증은 그대로 유지한다. 실제 운영 설정을 임의로 복사해 테스트하지 않는다.

## 2026-10-01: 저장 타임아웃 수정과 단일 저장 UX

사용자는 필수 미리보기·검토 체크 단계를 폐기하고 편집 중 참고용 실시간 요약 + 저장 한 번을 요청했다. 전체 및 폴백별 저장 버튼은 정확한 편집 초안·대상·연결 범위를 고정하고, 내부에서 기존 서버 계획 생성과 단일 토큰 적용을 순서대로 수행한다. 서버 revision/CAS/읽기 전용·관리형 설정 보호·범위별 허용 정보·중복 적용 차단은 유지한다. 계획 생성 실패는 저장 전 오류, 적용 시작 후 시간 초과는 결과 불명으로 구분하고 쓰기를 자동 재시도하지 않는다. 기존 사용자-facing 미리보기/최종 확인 체크 요구를 대체한다.

Desktop SDK request의 세 번째 숫자 인자가 외부 RPC 대기 시간이며 body.timeout은 하위 CLI 실행 제한이다. 외부 대기가 더 짧아서는 안 된다. 대량 적용은 프로필별 격리 worker에서 기존 `hermes_cli.config.config_command(set)` 디스패처를 재사용하여 항목마다 전체 CLI/패키지 매니저를 다시 부팅하지 않는다. 직접 YAML 쓰기를 구현하지 않고, 허용된 비밀 아닌 키만 전달하며 기존 키별 CAS·원격/관리형 보호·실제 읽기 검증을 유지한다. worker의 출력은 고정된 성공/실패 프레임만 반환하고, 완료·실패 시 task-owned process를 종료한다. 설정 읽기는 매번 정확한 파일 bytes를 읽되 같은 bytes는 Service 내에서 다시 YAML 파싱하지 않고 반환값을 복사한다. mtime만으로 캐시하지 않으며, 실제 변경·파싱 오류·관리형 provenance 검사는 계속 읽는다. 실설정 재저장 없이 격리된 11프로필 실제 CLI 저장/재조회 및 독립 Heavy 검수 후 코드만 설치한다.

## 2026-10-01: 이해하기 쉬운 폴백 UI와 전체 저장

사용자는 폴백별 비용·재실행 동의 체크박스를 제거하고 고지 문구로 대체하도록 요청했다. 폴백별 미리보기 확인 체크박스도 없애고 명시적 적용 버튼을 유지한다. 전체 미리보기의 최종 변경 확인은 유지한다. 기존 계약의 별도 체크박스 요구를 대체하며, 실제 예비 모델 선택·적용 없이 설치만으로 활성화하거나 비용 허용을 저장하는 것은 여전히 금지한다.

전체 미리보기는 모델·라우팅과 사용자가 수정한 폴백/복사 대상만 하나의 서버 계획으로 구성한다. 각 폴백의 적용 대상은 모델 일괄 대상과 독립적이다. 사용자 후속 요청으로 처음 열 때 편집 가능한 모든 프로필을 선택한다. 체크 초기화는 복사 의도로 취급하지 않고, 수정하지 않은 폴백은 전체 저장에서 그대로 보존한다. 수동 부분 선택·전체 해제는 프로필 변경/새로고침에서 확대하지 않는다. 라우팅 활성 목록은 실제 저장 상태를 그대로 표시한다. ‘불러온 프로필만’ 버튼은 위에서 불러온 프로필 하나로 대상만 좁히며 저장하지 않는다. 수정하지 않은 폴백은 인수·재승인·투영하지 않는다. 수정한 범위의 대상이 없으면 전체 미리보기를 차단한다. 범위별 미리보기/적용도 유지한다. 단일 토큰·revision·CAS·유효 설정 읽기·부분 실패·중복 적용 차단은 유지한다. 라이브 설정을 변경하지 않고 fake-home 저장 검증과 독립 Heavy 검수 후 플러그인 코드만 반영한다.
